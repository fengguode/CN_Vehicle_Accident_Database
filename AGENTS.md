# Codex project guidance

Track every project task, decision, finding, and follow-up in the shared [`updater-vnext/docs/PROJECT_BACKLOG.md`](../updater-vnext/docs/PROJECT_BACKLOG.md), including work in this repository. Keep stable IDs, owner, status, updated date, scope, blockers, acceptance evidence, linked QA/review notes, and this repository's current Git state there. Update it at each meaningful handoff and do not mark work complete without required QA/review and Git evidence. This is the single project-level status source; do not create a competing variant backlog.

This is a sanitized, static public ADAS incident database on a publication branch. Keep raw SQLite databases, logs, secrets, and private or identifying information out of published files. Preserve source provenance and the distinction between unverified leads and verified incidents.

Read this repository's README for behavior and commands relevant to the task. The primary agent owns each authorized task through implementation, focused verification, review, and a concise handoff. Make a short plan for substantial changes; keep small fixes lightweight. Delegate independent, bounded work only when it can proceed alongside useful primary-agent work. Give each subagent a scope, file ownership, and expected evidence.

Use the project roles in `.codex/agents/`: `controller` for cost/value and effectiveness reviews, `qualitymanager` for workflow, QA, and traceability audits, `explorer` for read-only codebase and evidence investigation, `system_architect` for stakeholder-led requirements and architecture decisions, `ui_designer` for complete interface and interaction design, `worker` for bounded implementation, `reviewer` for independent code review, and `user_tester` for project-wide test management. The System Architect traces requirements to owner/designer/user evidence and resolves material design gaps before dependent implementation. The Controller reports measured costs or explicitly labeled estimates and does not waive quality gates. For UI work, obtain design criteria before implementation and testing after a runnable version exists. Avoid overlapping edits. The primary agent fixes findings and verifies the integrated result.

Run the narrowest meaningful checks and report only checks that actually ran. Use `npm test` when relevant to code changes and available here. Use disposable data for mutating tests. Preserve existing user changes. Treat publication, live-service changes, Windows scheduled tasks, and real-account or production-data changes as separate operational actions that require task authorization.
